# 独立 Monitor 探针移除与节点脚本恢复

2026-10-25 用户要求移除独立探针模块，保留备份，心跳和管理恢复到节点安装脚本。

## 保留

- 全部协议节点、连接参数、订阅关联、SSH 档案、任务与故障历史。
- 节点安装脚本内置每分钟 cron 心跳、本地服务检查、自动修复和流量采集；执行后退出，无新常驻监控程序。
- SSH 按需运维；即使切换 SSH 管理也保留节点 cron 用于心跳，远端任务仍由 SSH 执行。
- 主面板“流量与通知”：协议端口流量图、节点额度、TG 配置、异常 / 恢复与汇总。资源压力通知改为读取节点脚本采样。
- 核心精简 / 原版安装、版本回滚、协议节点安装 / 重装。

## 移除

- `/monitor` 独立看板、主题安装 / 预览 / 配置、三网 TCP 探测、整机网卡流量看板。
- 服务器上的 Monitor agent 服务、二进制、独立配置和发布 cron。
- 面板的 Monitor hub 容器、主题运行数据、hub 配置与独立安装 / 发布脚本、主题上传 Nginx 例外。
- 安装节点与重装恢复不再提供独立探针选项。旧 `/monitor` 地址跳转回主面板流量页面。

## 迁移顺序

1. 用 SQLite backup API 备份面板与 hub 数据库并检查完整性，归档生产代码、源码、主题、二进制、Compose、密钥及 Nginx 配置；仅 root 可读。
2. 通过各节点现有管理通道更新原管理组件，恢复同机所有节点 cron，节点凭据认证后切换心跳来源为 `legacy`。
3. 等恢复任务完成，并确认该服务器所有节点产生新的真实脚本心跳，再下发独立探针卸载任务。
4. 通过任务回执及后续心跳确认探针服务卸载，最后停止面板 hub、移除独立路由与运行文件。

恢复脚本不重新安装协议，不生成新的 UUID / Reality 密钥或隧道，不更换节点链接。临时迁移任务保留审计记录；初次试点因缺少新资源映射返回 404，在修正下载接口后重试成功，没有修改协议配置。

## 备份

`/root/backups/auto-argo-monitor-20261025T110152Z/`，权限目录 0700、文件 0600。包含数据和私密配置，勿提交 GitHub。数据库与相应 `secret.key` 必须配套恢复；不要用运行中的数据库文件直接覆盖在线数据。

部分旧数据表继续作为服务器身份、历史记录及兼容核心升级使用，不再运行独立探针服务；它们不产生额外节点进程。

## 本次验证结果

15 台服务器的独立探针卸载任务均成功回执；16 个节点恢复脚本心跳并通过实际转发验证。与备份对照，所有节点 ID 与链接保持一致。主面板流量 / TG 页面及手机布局、服务器单机流量、旧 Monitor 重定向和已删除资源返回 404 均通过线上只读检查。
