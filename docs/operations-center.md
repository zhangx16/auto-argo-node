# 运维中心

左侧「系统运维」集中显示面板健康、服务器维护、版本和升级批次；节点的「故障详情 / 维护」提供单节点设置、检测结果与事件时间线。

## 维护与修复上限

- 单节点或已绑定服务器均可维护，支持 1 分钟至 7 天，0 表示结束。服务器维护对其绑定节点生效；结束节点维护不会解除服务器维护。
- 维护期间继续心跳、流量和实际转发检测，暂停受控自动修复、节点异常/恢复及修复通知；服务器维护也暂停该主机资源压力提醒。手动配置任务、已下发任务、操作系统服务管理器和协议自身重连不被中断。额度、订阅到期等独立提醒继续工作。
- 管理脚本 v8 每次修复前向 `/agent/repair-permit` 请求一次授权。默认每节点 60 分钟最多 3 次、两次至少间隔 5 分钟。可设 10–1440 分钟、1–20 次。
- 授权先持久计数，即使响应丢失也计入，宁可少一次修复。最后一次授权后暂停后续自动修复；时间窗口过去不会自动解除。检查结果后在详情页点击「解除暂停 / 重新计数」。此操作不解除维护，也不绕过 5 分钟冷却。
- 策略、维护期限及暂停状态保存在 SQLite，重启后保留。旧脚本无法完整执行该控制，必须升级至 v8；页面明确显示版本。管理脚本仍是每分钟运行并退出的 Shell + cron，没有新常驻进程。
- 维护开始前已经获得授权的修复允许结束，不强杀正在进行的服务操作。

## 故障详情

分别展示心跳、进程、本地监听以及从面板发起的实际转发检测。老监控模式有独立公网 WebSocket 检查；Monitor 模式不伪造这个检测。采样过期或采集器不可用标记为未知。

事件按北京时间展示，保留 90 天、全局最多 5000 条；不补造历史。导出 JSON 包含检查、维护/修复策略、最近任务状态及事件，不包含分享链接、凭据、原始配置或原始日志。节点名称和管理员填写的维护原因仍在报告中。

一次面板转发失败可能来自面板出站网络，不能单凭这一结果断言节点自身故障。已有探测重试、连续失败判定和修复冷却继续生效。

## 面板健康

复用 30 秒后台调度，健康采样最多每分钟一次，不另外安装监控栈。查看数据库写入探测、可用磁盘（低于 256 MiB 提醒）、Monitor、后台任务、等待/运行超过 30 分钟的节点任务和通知队列。超过 180 秒没有新观测标为未知。

Telegram 项目表示最近实际投递结果；Cloudflare 检查由管理员手动触发，只读取配置 Zone，不测试写入权限。未知和未配置不等于服务故障。异常/恢复复用已有 TG 队列和「异常与恢复」开关。

公开 `/health` 保持进程存活检查，详细状态仅登录后可读。面板完全停止、数据库完全不可用或 TG 本身不可达时，面板无法保证发出通知；需外部监控覆盖这些情况。

## 版本与分批升级

可选择管理脚本、资源探针、精简核心或固定原版核心。显示管理脚本版本、核心安装记录和探针安装摘要；未上报明确显示未知，摘要不是每分钟重新计算的二进制完整性证明。

1. 选择已绑定、启用管理的节点；每台服务器只选一个代表节点，共享核心/管理脚本会影响同机节点。
2. 确保最近 10 分钟实际转发成功，没有维护、未完成配置任务或配置验证。
3. 创建后首台先执行并验证，再逐台推进；同一时间只运行一个批次、一个升级项。
4. 管理脚本冻结各下载文件的 SHA-256；核心和探针冻结 release manifest 的 SHA-256，并沿用二进制下载校验。资源变化时停止，不混用版本；保留固定核心版本锁定规则。
5. 节点任务完成后再次实际转发验证。管理脚本还需上报 v8；探针还需有新鲜主机上报。任务失败、版本冲突、35 分钟超时或转发失败都会暂停后续节点。
6. 核心沿用已有基线验证与回滚逻辑。管理脚本保留既有本地回退文件；探针批次失败暂停，不承诺自动恢复旧探针二进制。
7. 手动暂停可以继续；失败项不会被自动跳过，请取消批次、处理故障后重新建立。取消或暂停不撤销已下发的节点任务。

批次进度持久化，重启后继续；保留最近 200 个批次，API 展示最近 30 个。待处理批次不自动删除。未启用管理的节点需在服务器执行安装 / 任务命令，不能静默打开管理权限。

## 验证与边界

隔离测试覆盖维护继承/到期、修复冷却与持久暂停、修复请求被拒绝时真实 Shell 不重启、任务冲突、报告脱敏、升级成功验证、失败暂停和资源变更中止。HTTP 测试检查登录、来源及输入校验。浏览器测试检查单模块路由、故障详情与运维中心，以及桌面和手机布局。

不进行 TCP 调参、自动测速或新增节点常驻进程。网络调优仍按 [保存的方案](network-tuning-proposal.md) 暂不实施。

## SSH 管理节点

可在 [SSH 运维](ssh-operations.md) 中切换管理通道。原队列、维护及修复上限继续生效，旧轮询通道在 SSH 模式下不再领取任务或修复授权。批量升级支持 SSH 执行；无主机探针的 SSH 节点以新鲜实际转发结果作为升级基线。升级前正在测活时等待结果，不把正在测活直接当成节点故障。
