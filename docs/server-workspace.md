# 服务器工作区、恢复与订阅隔离

## 页面入口

侧栏「服务器」统一提供三个视图：服务器档案、资源与流量、SSH 运维。旧的资源与 SSH 页面地址仍可打开，Telegram 旧跳转继续兼容。新服务器可先接入 SSH；需要自行执行脚本时，使用「生成手动安装命令」。

服务器档案沿用现有 SSH 服务器 ID，以显式节点关联和 Monitor 主机 ID 汇总信息，不按名称或 IP 猜测合并服务器，不重建现有节点或订阅关系。点击服务器卡片即可在当前页打开小窗，按「协议节点 / 运维与能力 / 档案设置」切换详情，汇总已安装的协议种类与数量。详情展示 SSH、探针、协议转发、系统能力和管理地址；密码和私钥通过原 SSH 对话框维护，档案接口不返回这些秘密。

## 一台服务器新增多个节点

在服务器卡片点击「新增节点」，输入名称、协议、监听端口及该协议需要的连接参数。SSH、主机指纹、管理地址与已有探针关联自动继承；节点 UUID / 密码和 WS 路径独立生成。节点显示、复制链接及订阅导出自动添加协议后缀：Argo 为 `-cf`、Reality 为 `-Vless`、Hysteria2 为 `-hy2`。已存在相同后缀不会重复追加，自定义原名保留可编辑，外部导入节点沿用原名。面板建议下一个未被已关联节点占用的端口，同 TCP/UDP 类型的端口冲突会拒绝提交。未手工指定直连公网端口时，它随本地监听端口同步变化；手工填写过的 NAT 映射端口会保留，端口不同时显示映射提示。此建议不代表供应商已经放行或映射该公网端口，安装器仍检查实际占用。

有 SSH 凭据时可勾选自动安装，创建持久恢复流程，依次进行能力检测、协议安装与实际转发验证。已有探针可复用，只增加节点关联与服务采样，不重复部署探针。单服务器内共享 sing-box 核心，新增节点沿用已有核心通道和管理方式；执行时使用现有服务锁和同机互斥。未选择自动安装时返回手动命令。

## 管理主地址与备用地址

主地址留空使用面板默认来源地址，备用地址最多三个。仅允许完整 HTTP(S) 来源，不允许账号、路径、查询或片段；填写的地址必须是管理员控制的面板或转发网关。地址在管理员保存后成为该服务器明确授权的凭据接收来源。

协议与探针安装命令按顺序尝试这些地址。带来源参数的 bootstrap 仅接受该服务器允许的地址，所选地址统一写入安装下载与回调配置。TLS 校验保持开启；不会自动使用一个任意发现的地址接收凭据。

对已有服务器，保存档案不会立即修改远端。点击「应用已保存的管理地址」后，通过 SSH 核验现有节点身份、检查地址 `/health` 连通性，再更新节点管理配置与探针环境并重启探针；不更改协议入口、端口或客户端链接。SSH 执行节点任务时也可从明确配置的主备地址中选择可用入口。健康检查只证明该来源可连接，管理员仍需核对来源归属。

## 系统能力检测

「检测系统能力」只读采集系统、架构、初始化方式、cgroup 内存上限、根分区空间、容器标识、公网 IPv6 地址及工具可用性，保存最多一天的缓存。安装流程仍会重新检查，避免拿旧结果直接安装。当前自动安装目标为 Alpine / Debian / Ubuntu、amd64 / arm64、OpenRC / systemd。能力检测不修改内核、安装依赖或突破容器权限，也不保证供应商已开放某个端口。

## 服务器重装恢复向导

1. 在档案详情选择「重装恢复向导」，先更新当前 SSH 地址、认证凭据与经过核对的新主机指纹。历史指纹不匹配时停止，不自动接受变化。
2. 选择需要恢复的节点，以及是否安装或修复探针。核对目标后明确确认执行。服务器已重装时，可选择取消这些节点尚未执行的旧排队任务；执行中或结果未知的任务不会自动放弃。
3. 先做只读能力检测，然后逐个按保存配置安装协议。每个节点必须有对应配置任务成功回调和新的实际转发成功结果，SSH 退出码为零不会单独判定成功。
4. 协议通过后安装独立探针，或复用现有探针；确认新鲜心跳和所选节点的进程、监听采样，再结束流程。

流程与步骤、任务 ID、预期配置版本和连接指纹均持久保存，面板重启后继续检查同一任务。失败暂停；明确确认远端结果后可继续当前步骤。转发验证暂停时可在流程内修正客户端公网端口和重新验证，不必重装已经成功安装的协议。安装验证优先于周期测活领取检测名额；等待检测队列不会直接算作节点转发失败。已经启动而执行标记丢失时保持结果未知，不盲目重放。取消仅停止后续步骤，不强杀远端进程；正在执行的 SSH / 协议任务需先处理。

恢复期间同机节点进入维护、配置修改互斥，自动 SSH 调度暂停。成功后只结束该流程创建且未被用户覆盖的维护状态，并恢复原来的 SSH 自动调度暂停状态；不会自动切换 SSH / 主动拉取模式。取消后保留自动运维暂停以便检查。节点 ID、订阅关联、标签和保存配置保留；临时隧道域名、Reality 密钥等可能在重装时变化，完成页显示链接是否变化，客户端需要更新订阅。

## 服务器任务记录

集中展示节点配置、SSH 执行、分批升级与服务器恢复记录，可按类型和状态筛选、分页查看。保留原节点任务明细及升级控制入口。错误按身份、认证、网络、超时、环境不支持、执行失败或结果未知归类；历史配置任务保存自己的错误，避免显示后续任务的错误信息。

SSH 输出逐行写入轮换文件，每段不超过 64 KiB，单行最多保留 8192 字节，面板最多显示脱敏后 24000 字符；执行中约每 10 秒更新缓存，页面约每 5 秒读取缓存，不为每个浏览器额外连接 SSH。Debian mawk 使用交互输入选项避免到退出后才刷新；Alpine BusyBox awk 使用兼容参数。未完成任务与结果标记仍沿用原有防重放设计。

## 订阅故障隔离与恢复

在订阅条目点击「故障隔离 / 恢复」。每个订阅独立设置，默认关闭；默认启用参数为连续失败 3 次且观察 5 分钟后隔离，连续成功 2 次且观察 5 分钟后恢复，次数与时间需同时满足。

只接收自建节点不同批次的实际转发检测结果，不用定时器重复累计同一结果，不把心跳丢失直接等同转发失败。维护、未知、过期结果不计数；观察中断会重置连续次数，配置版本或链接变化也会开始新的观察。已隔离的节点仍需经过恢复检查。

隔离只过滤该订阅导出，节点及原有选择关系保留，也不停止服务；同一节点可在另一个未启用隔离的订阅正常导出。代理链有一跳隔离时暂时排除整条链，不会删掉一跳后绕过；仅链式导出且全部链隔离时明确返回不可导出。关闭策略或修改阈值会清空该订阅的观察记录，重新开始。外部节点不参与自动隔离；客户端更新订阅后才能取得新列表。共享流量累计口径保持原样，不因隔离清零。

状态转换复用 Telegram 健康通知类别发送订阅、节点与变化结果，不附带订阅地址或认证凭据。

## 维护实现与资源边界

SQLite 沿用 WAL，增加 10 秒 busy timeout、明确的迁移版本记录、索引及 WAL 大小可见性；迁移集中验证旧表漂移并补列，不覆盖已有凭据或节点数据。没有引入新的数据库服务。

面板检测客户端共用最多 4 个进程的预算；预算不足的节点探测延后，不计为节点转发失败。同一 SSH 工作中的嵌套密钥验证复用中转客户端，最后一个连接关闭后退出。资源摘要按文件大小、mtime、ctime 缓存；安装器发现已安装二进制 SHA256 与冻结发布摘要相同时复用本地文件，仍执行摘要和配置验证。节点端不增加 Python 或新的常驻管理进程；这些改进不承诺未经测量的固定内存节省比例。

## 集中式服务器弹窗与独立看板

服务器弹窗扩至桌面最大 1280px、约 90% 视口高度，手机接近全屏。协议节点包含完整管理按钮；SSH 运维表单、能力检测、维护及本机升级、任务筛选与日志均在弹窗内操作。任务查询先按服务器限制再截取保留窗口，避免其他主机大量任务淹没本机历史。跨服务器升级批次在单机界面只展示本机条目，批次控制仍作用于整个批次。

资源总览现有独立入口 `/monitor`，沿用登录会话。支持在线汇总、搜索 / 状态 / 分组筛选、拖动排序、卡片或紧凑显示、主机流量控制和协议流量图。每个主机提供返回对应服务器工作区的链接。单机工作区仍可查看资源与流量；关闭弹窗后组件回到原位，各数据请求按当前服务器隔离。

完整功能清单见 [function-inventory.md](function-inventory.md)。

## 节点管理统一入口

独立已部署节点页面及导航已删除。服务器模块可按节点名称、地址、协议、分组和标签搜索，结果直接打开所属服务器并定位节点。未关联档案的记录集中在待关联节点区，保留完整节点参数、状态、日志、编辑、重装与删除操作，可选择已有服务器建立关联；关联不会重新安装协议或变更节点链接。

新节点通知链接使用 `/static/index.html?node=节点ID#server-module` 定位；旧 `#node-module` 回到服务器模块，带节点参数的旧链接仍可定位。订阅关联及节点 ID 保持不变。
