# 汇总订阅与紧凑节点管理

在订阅管理中创建或编辑订阅，勾选「引用已有订阅」，即可将多个订阅汇总到新地址。也可以额外直接选择节点；引用关系在本地解析，不抓取本机订阅 URL，不复制节点记录，不在节点服务器新增脚本或进程。

## 同步与去重

- 每次导出、预览和读取专属页时使用原订阅的最新成员和连接配置；客户端需要刷新订阅才会获取变化。
- 相同连接参数与认证信息只输出一次，忽略显示名称差异。相同服务器上的不同账户保留各自节点。
- 支持嵌套和多条路径引用。拒绝自身引用、循环及超过 8 层的关系；每个订阅最多直接引用 30 个来源，展开后最多关联 64 个订阅、1000 个节点、120 条链路。
- 原订阅的停用、到期和删除使对应分支停止导出，其他有效分支继续使用，面板和专属页提示原因。删除原订阅保留引用诊断记录，编辑汇总订阅可移除失效引用。
- 重置原订阅分享地址不影响本地引用关系。若要撤销它在所有汇总订阅中的输出，应停用或删除原订阅。
- 保留来源自身的故障隔离与链式配置；仅导出链式节点的来源不会把链路各跳单独输出。包含链式配置时仍只提供 Clash/Mihomo、sing-box 格式。汇总订阅直接配置的链路只使用直接勾选的节点，故障隔离策略同样针对直接成员；继承成员遵循原订阅策略。
- 来源后续增长导致合并超过上限时，超限分支停止合并并显示原因，不静默截取部分节点。保存新配置时遇到超限会拒绝并回滚。

## 流量统计

面板和订阅专属页按原订阅展示用量、额度、到期时间、采集是否过期。嵌套订阅展开到有直接节点的来源；同一来源经多条路径引用只展示一次，同一个上游账户被不同订阅引用会标注共享。同一上游来源只计一个用量来源。不同上游账户独立保留；不同计量范围、周期的额度和用量不相加。

客户端响应头 `Subscription-Userinfo` 仅能表达一组计数：

- **自动**：只有一个可确定的用量来源时提供该来源统计，多来源时不提供合并用量，前往专属页查看明细。
- **指定原订阅**：提供已引用订阅的用量与到期信息；原订阅本身是汇总时，使用它选定或自动识别的单一用量来源。
- 明确指定的来源停用、删除、到期或无法给出单一用量时不自动切换到其他账户。
- 汇总订阅和选定来源均有到期时间时，客户端响应头使用更早的到期时间。

这些计数仍是上游账户共享用量或自建节点共享端口计数，不是汇总订阅访问者的个人用量；不会限制或停止实际转发。

## 节点列表与删除

- 订阅默认折叠，展开后以紧凑网格显示自建及外部节点，手机使用两列；地址、标签和编辑等操作放在节点详情内。
- 已加入订阅的外部节点不再在外部节点总列表重复平铺；未加入任何订阅的节点保留在「外部来源与未归入订阅节点」。
- 外部节点支持单个删除、勾选批量删除、全选与清空选择。删除前显示受影响的直接和汇总订阅名称。
- **删除外部节点是全局删除**，会从所有订阅中移除，并在定时来源中标记排除，后续刷新不自动重新导入；远端服务器不受影响。仅调整一个订阅应编辑它的节点或来源选择。
- 批量删除在一次事务内完成：编号无效或节点已消失时整批失败，不部分删除。

## API

订阅请求增加 `included_subscription_ids`（默认 `[]`）、`usage_source_id`（默认 `0` 表示自动）。旧客户端更新时若不传这两个字段会保留原值。管理端响应保留 `node_ids` / `external_node_ids` 为直接成员，另返回来源状态与解析后的可导出数量，避免编辑时把继承节点复制进直接选择。

`POST /api/external-nodes/bulk-delete` 接收 `{"node_ids":[1,2]}`，要求管理员登录和同源请求，最多 1000 个互不重复的正整数；原单节点 DELETE 接口继续可用。实际订阅地址、上游认证和服务器凭据不写入本文档。
