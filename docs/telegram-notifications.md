# Telegram 消息与提醒

Telegram 使用现有 Bot 和接收聊天配置。消息以状态图标、粗体标题、关键字段、北京时间（UTC+8）和面板按钮展示；动态文本进行 HTML 转义，按钮只指向面板登录入口，不携带订阅令牌或节点凭据。格式依据 [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage)，使用 HTML 与 inline keyboard，兼容普通消息客户端。

在“流量与通知 → Telegram 通知设置”选择分类：

| 分类 | 触发与内容 |
| --- | --- |
| 异常与恢复 | 原有心跳停止阈值；非离线变化持续 60 秒确认；恢复附面板观察到的异常持续时间。区分心跳缺失和真实转发失败 |
| 部署与任务 | 节点回执成功或失败；成功回执明确标注等待转发验证，不宣称已可用 |
| 修复与变更 | 自动修复（同节点至少间隔 10 分钟）、临时隧道变更、配置验证、核心验证与回滚结果 |
| 外部订阅 | 连续两次已完成的更新失败提醒一次，成功后提醒恢复；更新中的任务不计为一次失败，不发送原始 URL 或错误正文 |
| 订阅到期 | 到期前 3 天和到期后各提醒一次；不补发已超过 24 小时的历史到期提醒；只影响订阅导出，不停止协议 |
| 持续资源压力 | Monitor 新鲜样本：CPU、内存或磁盘 ≥90% 持续 5 分钟，低于 80% 恢复提醒；采样中断重置持续窗口，按主机而非协议重复提醒 |
| 流量额度 | 保留配置的周期和阈值，新增可视进度条；仅提醒，不停用节点 |

发送时间、最后心跳和到期时间均转换为北京时间，已排队的旧消息也会转换。流量的日/月和额度结算仍使用原有 UTC 统计边界，并在消息中明确标注，避免改变既有累计值。

流量简报包含节点观测状态、采集覆盖、今日上下行、本月总量、今日 TOP 5 及条形图。无采集数据不会伪装成正常；端口统计不等于整机网卡流量或厂商账单。

所有新规则都在面板执行，复用已有事件、订阅记录和 Monitor 数据；资源读取每分钟最多一次，节点端无新增脚本或采样。Monitor 采集服务异常持续 60 秒后提醒，暂缓批量心跳告警，但真实转发失败仍可提醒。

通知保持每轮最多发送一条，告警优先于简报；队列最多 200 条，发送失败最多 8 次重试，超过 24 小时丢弃。已发送事件保留最多 2000 个去重键、最长 30 天；同节点待发健康状态被较新状态替换。首次启用新事件规则从当前事件位置开始，不回放旧任务日志。关闭分类会取消该分类未发送的消息。

“发送测试通知”发送明确标注的测试消息与当前简报，不模拟真实故障。消息模板不会包含 SSH 密码、Bot Token、UUID、订阅 URL 或原始任务日志。网页仍沿用原有布局，仅增加分类选择。

## 本轮验证

136 项单元/API 测试通过，覆盖格式转义、北京时间跨日、旧队列时间转换、恢复耗时、优先发送、分类关闭、去重、来源连续失败、订阅到期和资源压力窗口。桌面 / 手机分类控件验证通过；已部署并通过现有 Bot 发送明确标注的测试消息。

## Bot 快捷指令

左侧菜单使用 Telegram Commands，移除旧“我的面板”Web App 入口。提供 `/start`、`/status`、`/nodes`、`/traffic`、`/help`；仅响应当前配置绑定的聊天，不返回节点凭据或订阅令牌。菜单同时设置默认作用域、已绑定聊天及中文作用域。保存新的 Bot 或接收聊天时同步菜单。

面板沿用 30 秒任务循环读取最多 20 条 Telegram 更新，不新增节点进程；一般 30 秒内回复。同一批只回复最后一条有效查询，十秒内限制重复查询，超过 3 分钟的旧指令不回放。更新位置持久保存；异常时保留通知任务执行。快捷查询与异常通知开关独立，关闭异常通知仍可主动查询。一个 Bot 应由此面板读取更新，外部 webhook 或另一程序同时轮询会造成冲突，不会自动删除外部 webhook。查找聊天支持最近发现记录，避免指令轮询后找不到聊天。
